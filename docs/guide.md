# Jobdesk guide

How each screen of Jobdesk behaves. To install the app, see the [README](../README.md).

Jobdesk is a native macOS and Windows view over an [ai-job-search](https://github.com/ai-job-search-dev/ai-job-search) checkout, built with Rust and egui.

## Today

Today is the home screen: one queue of decisions, one card at a time, with paused runs first, then deadlines, then the rest. The day stamp counts what you decided today, and Coming up lists the next two weeks' deadlines, with a button to bring back what you set aside. Settings › Today queue changes the range to 7, 14 or 30 days, and the same range decides which deadlines come before the rest.

Y opens the suggested task, L sets the card aside (Coming up shows how many, and its button brings them back to the front, after any paused run) until tomorrow, or for as long as Settings › Today queue says, but never past the card's own date, unless that date is the day you press L or earlier: then it comes back the day after you pressed L, N skips, U undoes the last decision. Until your next one, and only that day, it waits at the top of Done today, where a skip also takes its optional reason. The reasons are your list in Settings › Today queue. A followed card's note names the task it opened, for example "Task opened: draft application".

The card's actions stay pinned under it, and Show the command reveals the command line a task would run. Y opens the slash command in the launcher, and nothing runs until you start it. Permission, question, guard and Your turn cards have no Y action. Skip reasons stay in the app's data folder, and a past skip keeps its reason after you take that reason off the list.

When nothing is left to decide, Today offers Find new jobs…, and Score 1 new job… or Score N new jobs… while new jobs wait to be scored. Both only open the launcher. Today shows a loading view while your files first load, and a welcome with three steps until you choose a folder. Its second step points to Profile, which shows each topic, what is filled in and what is missing.

## Jobs, Applications and Insights

Today, Jobs, Applications, Insights and Profile update live as commands change your files. A file that fails to load raises one alert that names what failed and what still works, and marks its tab. The screens it feeds say their content is hidden until the file is fixed, never that it is empty.

Click anywhere on a job, an application or a run to open it. On Jobs, Up and Down move to the next job while a row or nothing has the focus, and Tab stops once on each row. A cut title shows in full under the pointer. Below 1100 pixels wide, the table leaves out Found on, which the detail still shows. When Settings › Jobs view hides some jobs of the open list, a line above it says how many, such as "2 jobs hidden by Settings › Jobs view." Show them lists them again, and Hide them hides them.

Insights' Profile stage counts how many profile topics are filled, not files, and says how many are hidden when a file cannot be read.

## Application dossier

Open an application from Applications for its dossier: compiled PDFs, verification results, keyword coverage, evaluation, archived posting, prep packs, outcome notes and follow-up drafts. Verification, keywords and evaluation exist only in `/apply` output, so they appear for applications run through Jobdesk.

## Tasks

The Tasks screen starts any slash command through your local `claude` CLI and shows its progress, questions, cost and history. Jobdesk allows tool permissions by default and lists each one in the activity. Settings › Permissions turns prompts on.

A run reads like a report: Claude's messages come first, and each step is one plain sentence, with its actions a click away. A message's text keeps to a readable column, and a table that stands on its own uses the whole width of the run, scrolling sideways only when wider still. A table of two or more columns fills that width, and a table of a single column keeps the width of its cells. A table inside a list or a quote keeps to the column, and so do a message's tables when a footnote points across one. A band at the top says where the run is, whose turn it is and what comes next.

While Claude works, a short line sweeps along the bottom of the Whose turn cell to show the run is live, and the cell says how long ago the last update came. Your reply, or your answer to a question or a permission prompt, counts as an update too. When nothing new arrives for 30 seconds, the sweep turns grey and slows down. After 2 minutes it stops and becomes a dashed line, and the band says for how long it has been quiet. A long write can be quiet for minutes, and Stop run keeps the files so far. While Jobdesk stops a run, the line stands still and solid.

In the run's details, Elapsed counts every second from your send until the run ends, so your own turn counts too. It holds once the run is done, failed or stopped, and a later reply adds a new stretch to the held figure. It reads 0:45, 14:20 or 1:02:05. The run log keeps no clock, so a run you reopen from its history, after a restart or a folder switch, shows only the time Claude reported for its own work. The time you spent away, waiting turns included, is not kept, so it can read less than it did live. A later reply adds clock time on top. Cost counts up as an estimate marked About, with the line "Estimated until Claude's turn ends.", and shows the exact cost once the turn ends. The estimate is approximate and can be off in either direction, because it prices each model family at one list price. The exact figure replaces it. A session that ends with no result, such as after Force stop, keeps its estimate marked About for good, and the line then reads "Includes an estimate: a session ended without its final cost." A run you resume adds the cost of each session, also after a restart.

When Claude waits on you, the Tasks tab counts it, Recent runs tags the run Your turn, Today deals a card that opens the task and shows its cost as Tasks does, About included, and Claude's question sits above the reply box, with one-click replies at known stop points such as /apply's proceed with drafting. They wait while you write a reply of your own. When Claude finishes a turn without asking anything, the band says it is done for now and the reply box stays under the story.

End session asks first, and Keep it open is the default. New task (Cmd+K, Ctrl+K on Windows) opens the command launcher, even while you type in a field. In the launcher, Cmd+Enter (Ctrl+Enter on Windows) runs the task, and Esc goes back.

Quitting while a Claude session is open asks first. Keep working is the default, and Esc keeps working too. End session and quit ends the session, and you can resume it later from Tasks.

## One run at a time

Only one run works at a time, because two commands could overwrite each other's files. A session waiting for your reply lets a new run start only once its turn has ended and all its background agents have finished. A Save on the Profile screen waits for the run too. Restart to update waits while a Claude session is open, even one only waiting on your reply: end the session in Tasks first.

## Copying text

Text in Claude's messages and questions, your replies, error alerts, command lines, company research, archived postings, follow-up drafts, the Profile paper and the folder path in Settings › General can be selected and copied. A question cut to fit is not, and shows in full under the pointer. Copy says Copied.

## Settings

Settings (Cmd+, on macOS, Ctrl+, on Windows, or Settings at the right of the status bar) replaces the menu and the screen until you press Back to app or Esc. A task keeps running meanwhile, and the status bar says when one waits for you. The rail groups the sections under Personal, Job search, Models and providers, and System, in the order below. A word beside a section says its state where it has one: the theme beside Appearance, what is missing or still to fill beside Runtime status, this month's spend beside Usage statistics, the sign-in tasks use, or Key refused, beside Providers, how many of your terms are not stated, or Hidden when their file cannot be read, beside Your terms, and beside About the version you run, an update's news such as 0.2.0 is out or 0.2.0 ready, or Check failed. Search keeps only the sections with a match and marks the matched words. Esc clears the search first. Changes apply at once and stay on this computer. If the settings file cannot be read, the rail's foot says so: the defaults are in use, and your next change replaces the file. If a change cannot be saved, it says the change lasts until Jobdesk closes. On the first launch after the theme moved into Settings, the theme and text size you had are kept. An older version of Jobdesk drops the settings it does not know the next time it saves the settings file, so it forgets the sign-in you chose and its tasks use the Claude sign-in. Your API key stays in the keychain. Back on this version, choose Use for tasks on the API key again.

- General: your job search folder, with Show in Finder (Show in Explorer on Windows) and Change folder, and the screen Jobdesk opens on. Without a folder, Jobdesk opens on Today. While a Claude session is open, even one waiting on your reply, Change folder waits here and on Setup, so the task keeps its folder. In Tasks, stop it (Stop run) if it is working, then end it (End session).
- Appearance: the theme (System, Light or Dark), the text size from 90 to 150 percent (Cmd + and Cmd −, Ctrl + and Ctrl − on Windows, change it too), and Reduce motion, which drops the card slide and the day stamp's fill and stills the live sweep on Tasks into a solid line, dashed once the run is long quiet.
- Usage statistics: what your tasks cost and did, from Jobdesk's own run logs for this folder. It counts tasks only and fetches nothing. A period toggle picks the current month, the last 90 days, This year or All time. Four figures follow: Spent, Tokens in (with tokens out in the note), Cache hits, and Tasks, split into finished, stopped and failed. Per application sent divides every task's cost by the applications you marked sent in the period, and hides when there are none. Below sit the last 12 months by day: hover a day, or Tab to a day with tasks, to see its date, tasks and spend. Then come two tables, By command and By model.
- Your terms: the lines a job may not cross, which Jobs checks every posting against: the contract rule, Freelance only, your day-rate floor from `01-candidate-profile.md`, and your commute tiers from `04-job-evaluation.md`. Jobdesk only shows them: change them with Edit in Profile, which opens Profile, or with Update with Claude…, which opens the launcher. A term your files do not state reads Not stated, and its check reads Unclear instead of guessing. Without commute tiers, a fully remote job still passes the commute check, and a place the location check ruled out still fails it. When a file cannot be read, its terms are hidden, not gone, and Update with Claude… waits until it reads again.
- Today queue: the Coming up range (7, 14 or 30 days, 14 by default), which also sets which deadlines Today deals before the rest; how long Later lasts (until tomorrow, the default, 3 days, or until Monday); and the skip reasons a skip offers, Rate, Scope, Domain and Location by default. Add or remove reasons, up to 8 of 40 characters each. Past skips keep their reasons, and a reason stays optional. A card set aside keeps the return day it had when you pressed L, unless a deadline it gets meanwhile comes first: then it comes back on that day, or the day after you pressed L when the deadline is the day you pressed L or already past.
- Jobs view: hide jobs that fail the day-rate, commute or language check, jobs scored under a number (60 by default), and jobs the safety check flagged. All start off. The filters hide rows only: no job changes list, because `/rank` keeps the lists. A flagged ad still comes to Today as Check this ad, and once you keep it there, Jobs shows it again. A job not yet scored is never hidden by the score.
- Providers: how tasks sign in. Claude sign-in, the default, uses the sign-in of your installed Claude Code, and Jobdesk stores nothing for it. To switch account, run `claude` in a terminal, then `/login`. API key: paste an Anthropic Console key and choose Save key. Jobdesk keeps it in the macOS Keychain (the Credential Manager on Windows), never in a file, and tests it at once. While a task is open, or another test is finishing, it waits at Not tested yet instead: choose Test connection or Use for tasks once that ends. Tasks switch to the key only once the test passes, so a mistyped key never breaks your next task, and a refused key leaves them on the Claude sign-in. A saved key shows only as `sk-ant-`, dots and its last four characters. Replace opens the field again, and Remove asks first, then deletes the key and puts tasks back on the Claude sign-in. Jobdesk first reads the key from the keychain when you open Providers, test the key or start a task on it. If that read failed, for example because you denied the prompt, the next test or task asks again, and Providers only shows why it failed. It keeps the key in memory until you quit, or until Remove has deleted it from the keychain. Saving or removing a key may ask for your password too, and choosing Always Allow stops the prompts. While a task is reading the keychain, the API key section says Waiting for the keychain… and offers nothing to do until it answers. A release is signed with a Developer ID, so Always Allow survives its updates. The first signed release asks once more, because its signature differs from an ad-hoc one. A build made from source or from the Actions tab is ad-hoc signed, and macOS may ask again after each update of it. The prompt offers no Touch ID. Test connection asks Claude Code one fixed question, with no tools, in an empty temporary folder. It costs about a cent, is not a task and is not counted in Usage statistics, and it waits while a task runs. When it fails, it shows what Claude Code said. If `ANTHROPIC_BASE_URL`, or a proxy variable such as `HTTP_PROXY`, would send the key over plain http, Jobdesk refuses to send it, and neither a task nor Test connection starts: use https, or http to this machine only, with no proxy variable set. Cloud providers come later.
- Run defaults: the model and Spend at most that each new task starts from, a table of commands with their own model and budget (a command's row beats the defaults, and Add a command picks from the commands Jobdesk knows), and a monthly cap. Left empty, Spend at most keeps each command's suggested budget. You can still change both in the launcher. At or over the cap, Run is disabled with the reason and a link back to the cap, and it opens again on the 1st. A task already running is not stopped, and replies in a session already open still send. The cap counts this month's tasks in the open folder, as Usage statistics does. Right after a task ends, Run waits until its cost is read.
- Permissions: Allow and note in the activity, the default, or Ask me before each tool. Either way, questions from Claude always reach you, and a rule you let it remember lasts only until the task ends and is never saved to your folder.
- Runtime status: Claude Code's version and the sign-in the last task used, then how many profile topics are filled, with Open Profile, and your tools, portals, templates and sync, as Setup shows them. The tools' ready count leaves out Claude Code, which has its own row above. Until a folder is chosen and read, only Claude Code and the tools show, and a search matches only those.
- Data and privacy: where Jobdesk keeps its data, with the size of the run logs and the tray decisions. Keep run logs for 30 days, 90 days or Forever, which is the default. A shorter time deletes older logs when Jobdesk starts, never those of the current month, and Usage statistics then counts only the logs kept. Clear tray decisions asks first and forgets what you decided on Today in this folder, with the reasons given for past skips. Your list of skip reasons stays, and other folders keep theirs.
- About: the Jobdesk and Claude Code versions with Copy details for a bug report, Updates, How tasks sign in, which says Claude Code signs in on its own and Jobdesk keeps only an optional API key in your keychain (Credential Manager on Windows), with Open Providers to go there, which also clears a search, and a link to the changelog. The licences are not available there yet. In Updates, Check for updates automatically is on by default: when Jobdesk opens and about every 6 hours, it reads the latest release on GitHub, and it downloads nothing until you choose Download. Off, Jobdesk looks only when you choose Check now, which looks whatever the switch says. Latest version reads Not checked yet, Checking…, Up to date with when it last checked, or Check failed with why. A failed check changes nothing on this computer, and Jobdesk tries again in about 6 hours while the switch is on. Once a newer version is known, Latest version names it, What's new opens its notes, and the next step takes Check now's place: Download 0.2.0, Cancel, Restart to update or Retry, as in [the status bar](#setup-and-the-status-bar).

## Profile

Profile shows what Claude reads about you, one topic at a time, on paper beside a rail of topics. On your CV holds Identity and languages, Experience, Education, Skills, Projects and publications, References and Profile statements. What guides Claude holds How I work, Goals and deal-breakers, Interview stories and Job search. Each topic reads Not started while its sections hold nothing but headings, blank lines and comments, N to fill while it still holds placeholders such as `[FIRST_NAME]`, and Filled when none are left. It reads Hidden when a file that holds it cannot be read, and the alert under the head says which. A fresh checkout reads N to fill for every topic, and the screen opens on the first topic with something left to fill.

The paper shows each topic as its files hold it, placeholders included, as written. Its text keeps to a readable column, and a table of two or more columns fills the width of the paper. Only a role's title, company and dates line shows them as "to fill" blanks. A placeholder counts where the page shows it, in text or in code, never in a link's address or in HTML such as a comment. Notes the templates keep in comments stay off the paper. The footnote names the file and headings the topic is kept in. Parts from your `CLAUDE.md` read "Summary in CLAUDE.md" or, for example, "Certifications in CLAUDE.md", and only its Candidate Profile part shows, never the rest of that file.

Update with Claude… opens the launcher on `/setup --section` for that topic, and nothing runs until you start it there. It plays out in Tasks. In a test, one topic took about three turns and cost about $1.00. It waits while another run works and while the topic's file cannot be read. Interview stories and Profile statements have no setup section, so you edit them by hand only. A topic not started offers Update with Claude… where it can, and Write it myself, with the outline it will hold faded below.

When a task ends, each topic it changed carries Updated on the rail, and the topic's head says which blocks changed and when. Opening the topic clears its rail mark, and leaving it removes the head line. The marks compare your profile when the task started with the first read after it ended, so a change made outside Jobdesk while a task runs is marked too. They last until Jobdesk closes.

Edit on a role or block, and Edit section on a section, open its text in place. Add a role opens a new one after the last role, and Write it myself opens the whole section. One editor is open at a time. Preview shows the draft as the paper will. Save (Cmd+Enter, Ctrl+Enter on Windows) writes only that block and leaves the rest of the file as it was. Cancel (Esc) closes the editor. While you type, the first Esc leaves the field. With unsaved text, Cancel, opening another topic, leaving the tab, changing folder and quitting ask first, and Keep editing is the default.

While a task runs, Save waits, because the task may change the same file. Your draft stays, and you can save once the task ends and Jobdesk has read the files it changed, which takes a few seconds at most. Just before it writes, Save reads the block again. If it changed on disk since you opened it, Save writes nothing and shows Changed on disk with the block's new lines. Use the new version replaces your draft with them, and Save mine over it writes your draft over them. If the block is gone from the file, Save mine over it puts your draft back at the end of its section, or at the end of the file when its section is gone too. Changes elsewhere in the file never stop a Save.

CV documents, the one row of Built from your profile, stays pinned under the topics and previews the CV PDFs in your folder's `cv/`. Its row reads N out of date, N documents, None yet when `cv/` holds no `.tex` or PDF, or Hidden when `cv/` cannot be read, and then the alert says your topics still show. The list puts your master CVs first, then each application's CV, newest first. Each CV carries one tag. Current, Source newer and Not built yet come from the modification times of its `.tex` and its PDF: Current when the PDF is as new as its `.tex` or newer, a PDF saved in the same second included, Source newer when the `.tex` changed after the PDF was built, and Not built yet when a `.tex` has no PDF. A PDF with no `.tex` reads Current, with nothing to build it from again. Render failed comes from drawing the pages: Jobdesk could not draw a PDF that is otherwise Current. A PDF is drawn when you pick its row, the first one when CV documents opens, so Render failed shows in the list only for a CV you opened since Jobdesk started. A CV that is out of date keeps its tag, and its pages show the failure. A PDF that fails within 30 seconds of being written, as while a task still writes it, is drawn once more the next time Jobdesk reads your folder after the file has stood still for 2 seconds. Only the first 6 pages show, and the line under the name says so when a PDF has more. Jobdesk never builds a PDF. `/build-cv` is the ai-job-search command that builds a CV's PDF from its `.tex`: it takes a CV's name, `--all` or `--list`, and the launcher lists it with the profile commands. Rebuild the PDF… and Build the PDF… only open the launcher on `/build-cv` and that CV's name, and nothing runs until you start it there. They wait while a task runs. They show only when your folder has the `/build-cv` command. Without it, the line says the folder has no `/build-cv` command and suggests updating your ai-job-search checkout. A CV whose file name holds anything but unaccented letters, digits, `_` and `-` gets no button either: type the command in the launcher. Open PDF opens the PDF in your PDF viewer, and Show in Finder (Show in Explorer on Windows) shows the PDF, or the `.tex` when there is no PDF. Files whose names hold hidden characters, and files that lead outside your folder, are not listed.

## Portals

Portals shows the job boards Claude searches when you find new jobs, each one a folder under `.agents/skills` in your checkout. The head says how many are on, and Check all portals… opens the launcher on `/scrape health`. Nothing runs until you start it there. Under the head, three tabs: Your portals with its count, Browse community and Add a portal. The screen keeps the tab you left it on, your search and what you typed in Add a portal while you visit other screens.

### Your portals

The list sits beside the picked portal's detail, and the first portal is picked when the screen opens. Each row shows the board's name and country with its switch, one sentence on what it searches, the jobs it found and the day of the last new one, and its tags. Built-in portals ship with ai-job-search, Community ones come from the community list, and Made by you covers any other, such as one built with `/add-portal`. Needs API key and Personal use only say what the portal's own file says. On portals come first, under "Claude searches these", then Off ones, quieter, under "Claude skips these". A row whose switch you flip keeps its place, so nothing moves under the pointer, and joins its new group the next time the screen opens.

The switch writes at once: Off sets the `enabled:` line in the portal's `SKILL.md` to `false`, adding one when there is none, and On sets it back to `true`, so `/scrape` skips or searches that portal from the next task on. It writes the way a profile save does, and the same kind of leftover copy can sit beside the file. A portal whose `SKILL.md` has no settings block at its top cannot be switched off, and the detail says so. While a task runs, every switch and action waits and says why on hover, because one task works at a time and `/scrape` reads the same files.

With no portal installed, the screen says so and offers Browse community and Add a portal, which open those tabs. When `.agents/skills`, or a portal's `SKILL.md` in it, cannot be read, the alert says why and the portals are hidden, never called none or counted short. Browse community and Add a portal still work.

### A portal's detail

The head shows the name, the switch, the country and sentence, the jobs found, the last new job and the tags. Check this portal… opens `/scrape health` on that portal, and Change search terms… opens `/setup --section search`, the same task as Update with Claude… on Profile's Job search topic, because every portal shares one set of terms. A portal whose folder name holds anything but letters, digits, `_`, `.` and `-` has no Check this portal…: type the command in the launcher.

Remove… asks first, with Keep it as the default and Esc keeping it too. Remove moves the portal's folder to the Trash (the Recycle Bin on Windows), never deletes it, and the jobs it found stay in Jobs. To use it again, put the folder back. Built-in portals have no Remove, only Off.

How it searches says in plain words whether the portal keeps a term of several words together, from its own `Query syntax:` line, and that each term is its own search. Searches it will run lists your shared search terms by priority, each as this portal receives it: in quotes for a portal that honours them, bare for one that ignores them, with a term that still holds a setup placeholder marked To fill. A priority with no plain terms says Claude takes its terms from its Google lines. If it fails shows the `site:` lines from your search terms that name this portal's site, which Claude searches Google with instead. The footnote names the portal's folder and the search file.

The screen shows no location or date window: those come from `/scrape` and your search file, not from anything Jobdesk reads per portal.

### Browse community

Browse community lists the portals other people share in the [community list](https://github.com/ai-job-search-dev/community-portals) on GitHub, grouped by country: your market first, marked "your market", then Worldwide, then the other countries by name. Your market is the country at the end of the Location line in your profile's Identity. When it has no community portal, the list says so and offers Add a portal. The search field keeps the portals whose name, country or sentence holds what you type.

Each entry shows the portal's name over its sentence, its owners on GitHub as plain words, and Maintained, or "Unmaintained since" a month when its owners marked it so. View code ↗ opens the portal's folder on GitHub in your browser. A portal you already have reads Installed, matched by its folder name, and it reads Community in Your portals, with its country. The others offer Install…, which opens the launcher on a task in plain words: Claude copies the portal into `.agents/skills/`, reads its code and tells you what it does, then asks before it runs the installer for the portal's tools. Nothing runs until you start the task. The note above the list says why: community portals are code other people wrote, and it runs next to your career data.

The line at the right says when the list was read, "From GitHub, updated 12 min ago", with Refresh. Jobdesk reads the list when you open Browse community and the copy it saved is missing or over an hour old, and when you press Refresh. While it reads, the line says so. When GitHub cannot be reached, the saved list stays, an alert says when it was saved, and Refresh becomes Try again. After a failed read, opening Browse community again reads nothing for a minute: press Try again to read at once. When GitHub's limit for requests without sign-in is used up, the alert says the time to try again after, and Try again waits until then. With no saved list and none read, the screen says the list could not be read, with Try again and a link to the list on GitHub. Your own portals are not affected.

### Add a portal

Add a portal has Claude build a portal for a job board you name. Type the board's website, where it lists its jobs. Country, Language of its job ads and One job title to test with are optional: what you fill in goes on the task's line, so `/add-portal` does not ask for it again, and it asks in the task for what you left empty. A website without `https://` at its start gets it, and one with a space is refused, because no web address holds one. Build it with Claude… opens the launcher on the line, such as `/add-portal https://jobs.sample-board.example country: Belgium, language: French, test title: Lead Backend Engineer`, and waits, saying why beside it, until the website is a web address. A field holding a character that does not show makes no line, and the form says which field to type again. Hide the command hides the line under the button, and Show the command shows it again. It is a task, so it costs like any other and shows in Usage. The new portal joins Your portals tagged Made by you.

## Setup and the status bar

Setup shows whether your profile, tools, portals, templates and sync are ready. Its Profile panel is one line: how many of the eleven topics are filled, how many are hidden if a file cannot be read, and Open Profile, which opens the Profile screen. With no profile file found, the panel, like the Profile screen, offers Set up your profile…, which opens `/setup` in the launcher. Writing style and cover letter templates no longer show there. Its Portals panel is one line too: how many portals are on and the jobs every installed one found, on or off, with Open Portals, which opens the Portals screen. With no portal installed it reads "No portals installed.", and Open Portals stays. While your saved jobs cannot be read, the jobs found hide, and while `.agents/skills` or a portal's `SKILL.md` cannot be read, the portals hide. Check portal health and Add portal moved to the Portals screen. Setup's tab stays in the menu only while a required item is not ready, so through your first setup too, and comes back if one goes missing later. A required item is your job search folder or a required tool. Your profile never keeps the tab. Optional tools never keep it either, and never count against the ready total. Settings › Runtime status always shows the same. The status bar says "Claude is ready", or "Claude Code is not installed". Before you choose a folder it says "Claude is installed. Tasks use its sign-in, or an API key you save in Settings." The theme is set in Settings › Appearance.

When a new version of Jobdesk is out, the status bar shows it to the left of Settings, one state at a time:

- "Jobdesk 0.2.0 is out", with Download.
- "Downloading 0.2.0", with a bar, the share and size done, and Cancel.
- "0.2.0 is downloaded and checked", with Restart to update.
- A failed download, with why, such as "Download of 0.2.0 stopped at 41%: the connection dropped", and Retry.
- "0.2.0 failed its signature check. It was deleted, not installed.", with Retry.

Up to date, checking and a failed check show nothing there: Settings › About says them. Click the words to open the release notes above them: the version, its release day, the version you have, and the notes. Links and images in the notes do not open. Below them sit the next step, the size, and Open the release page. Once the download is ready, a note above the step says what Restart to update does. Esc or a click outside closes them.

Download only downloads and checks the file's signature, and nothing installs until you choose Restart to update. A download stays until Jobdesk next opens. If you quit without restarting, Jobdesk deletes it then, and you download it again.

Restart to update closes Jobdesk the usual way, so an unsaved Profile edit asks first, and Keep editing calls the restart off. If the release is withdrawn before the window has closed, even after you chose Discard, the restart is off: any ask closes, and Jobdesk stays open with your edit. It waits while a Claude session is open, and its reason shows on hover, in the release notes and under Latest version in About: a task running, a task waiting for your answer, or a task waiting for your reply. Jobdesk then checks the file's signature again, installs it and opens again with the same folder and settings. On macOS it replaces the app where it is. On Windows the installer shows its progress in a small window for a moment, and it closes any other Jobdesk window that is still open.

If Restart to update could not install, Jobdesk opens the old version again where it can, and at its next launch the status bar says why, such as "0.2.0 was not installed: the new copy could not be put in place". The other reasons are that the downloaded file was gone or no longer matched its signature, that this copy was not installed by a Jobdesk installer, or that the new copy did not start. Retry shows once the next check finds that release again.

Some copies cannot update themselves. In place of Download, the notes and About say why:

- "Jobdesk cannot replace itself where it is installed." On macOS, a copy that runs from the disk image, or that macOS moved aside to open, says this.
- "This copy was not installed by a Jobdesk installer, so it cannot update itself."
- "This build has no update key, so it cannot check a download." A build made without an update key it can read says this.
- "Jobdesk publishes no build for this computer, so it cannot update itself." Such a copy checks nothing, and About says this under Latest version.
- "This copy has no version number Jobdesk can read, so it cannot tell whether a newer one is out." Such a copy checks nothing, and the word beside About reads Version unknown.

The first three add "Install 0.2.0 from the release page." and offer Open the release page.

## Privacy and trust

Slash commands write your checkout. Jobdesk changes it only when you save a Profile edit, switch a portal on or off, or remove a portal, and never while a task runs. A Profile save writes only that block of its profile file, and only when the block on disk is as you opened it or you chose Save mine over it. That check happens a moment before the write, so if another program, such as an editor, a sync tool or Claude in a terminal, writes the same file at the moment you save, Jobdesk can overwrite that change without warning. A portal's switch writes only the `enabled:` line of its `SKILL.md`, and Remove moves the portal's folder to the Trash (the Recycle Bin on Windows) after you confirm. A file named like `<file>.jobdesk-save-…` beside a profile file, or `SKILL.md.jobdesk-save-…` in a portal's folder, is a copy left by a save or a switch that was interrupted, for example by a power loss: it holds that file's text, a later write removes it once it is an hour old, and you can delete it yourself. Because Jobdesk allows the commands' tool requests without asking unless you turn prompts on in Settings › Permissions, a posting written to trick Claude could get a command run before you see it. The workspace checks postings with `posting_guard` before scoring them. Jobdesk uses the sign-in of your installed Claude CLI and keeps no password or token of its own, with one exception: an API key you save in Settings › Providers stays in the system keychain, and in Jobdesk's own memory from its first read until you remove it or quit, and reaches only the Claude Code process of each task, in its environment, never a file, a log or the screen. While a task runs on the key, other programs running as your user can read it from that process, as they can read Claude Code's own sign-in. Run logs, which include the text of your runs, and your tray decisions are kept in the app's data folder and are readable only by your user. Run logs stay there forever unless you choose a shorter time in Settings › Data and privacy. Unless you switch it off in Settings › About, Jobdesk asks GitHub for the latest release when it opens and about every 6 hours. The request carries Jobdesk's version and nothing about your job search. A download goes to the `updates` folder beside the run logs, and is deleted when it fails its signature check and when Jobdesk next opens.

Browse community reads the community portal list from GitHub, without sign-in. It is not a task: it starts no Claude, writes no run log and is not counted in Usage. It reads only when you open Browse community and the copy it saved in the data folder, `portals/community.json`, is missing or over an hour old, or when you press Refresh, and it sends only Jobdesk's version. GitHub allows 60 requests an hour without sign-in, and each read uses 2 of them. When they run out, the saved list stays until GitHub's reset time.

See [Trust](architecture/trust.md#rendering-untrusted-text) for how Jobdesk renders postings, notes and reports, [The community portal list](architecture/trust.md#the-community-portal-list) for how it reads the community list, and [Updates](architecture/trust.md#updates) for how it checks a download.
